The hard part of an internal library isn't the code. It's that four teams have to
agree the thing is worth depending on, and none of them owe you that.

## Headings are just hashes

Two hashes for a section, three for a subsection. The styling comes from the
design system — you never touch a class name.

## Code blocks

Three backticks, the language, and optionally a title. Highlighting happens at
build time, so nothing ships to the browser:

```cpp title="include/routing/leg.hpp"
// A leg owns nothing. Callers keep the waypoints alive.
class Leg {
public:
  Leg(std::span<const Waypoint> pts) noexcept;
  [[nodiscard]] Distance length() const noexcept;
};
```

## Showing instead of telling

This is where a technical blog can be genuinely different from a static page,
and it's the one flourish that doesn't cost cleanliness — it lives inside the
post rather than around it. Drag the slider[^1]:

A reader who drags that slider understands the tradeoff in about four seconds.
Three paragraphs of prose would not get there.

> The API you ship is a promise about what you won't change. Write it like you
> mean to keep it.
